SCOPE
Repairs the shared View Triage Result failure on the saved V3.3 baseline.
Does not change charge evaluators, legal content, hosting, or access.

REPRODUCTION
The V3.3 Theft of Services workflow was completed through rendered controls in
jsdom. Clicking View Triage Result threw:
  TypeError: Cannot set properties of null (setting 'innerHTML')
The result stayed empty. evaluateCurrent() expected #formError, but the current
single-question wizard supplies #flowMessage instead. The same evaluator entry
point is used by all charge modules.

FIX
- Use the active wizard message box, with legacy formError fallback.
- Missing optional message containers no longer stop valid evaluation.
- Required facts still block incomplete triage with a visible message.
- Unexpected evaluator/render errors show a message and keep entered answers.
- Clear stale/partial results and result metadata on a caught failure.
- Mark the workflow error area as an alert for assistive technology.
- Bump the visible version and service-worker cache to V3.3.1.
